## VERDICT: Reject

Two critical, three high, three medium, three low. The pattern of the previous review
repeats one level deeper: the fix for a fail-open path introduced a new fail-open path, in
the exact place the code now claims that is impossible.

### CRITICAL

**1. `scan_or_die` is fail-open — in the spot declared "enforced by construction".**
`core/scripts/check.sh:202-210`: `exit 1` runs inside the command substitution at line 225
(`hits=$(scan_or_die … | grep -Ev … || true)`), so it terminates the SUBSHELL only. The
main script continues and can print `CHECK: PASS`. Reproduced:

```
FAIL [scan]: scanner failed          <- stderr, printed
MAIN SCRIPT STILL RUNNING, hits=''
would print CHECK: PASS here
exit=0
```

Both the self-test closing message (`check.sh:150`) and `docs/ACCEPTANCE.md` state the
scanner-failure path is "enforced by construction — scan_or_die exits rather than
returning". That sentence is false. This is the previous review's finding about the
`|| true` pipeline, reintroduced by its own fix — the third occurrence of RESEARCH_LOG
backflow finding #6 across two repositories.

Fix direction: the failure signal must cross the subshell boundary. A flag file in `$work`
written by `scan_grep` on internal failure, checked by the main shell before the final
verdict, closes the hole structurally — including for project-written boundary checks that
call `scan_grep` inside `$()`.

**2. `guard_boundaries.py` never sees the Edit tool's content.**
`overlays/claude-code/files/.claude/hooks/guard_boundaries.py` reads the edited text from
`new_str`; Claude Code's Edit tool sends `new_string`. The hook therefore inspects Write
calls only, and every violation written through Edit — the most common editing tool —
passes silently. The hook is installed-looking and inert. The same bug exists in the
founding project's own `.claude/hooks/guard_boundaries.py`, from which this file was
extracted; the fix must flow to both (kit first, per docs/UPDATING.md).

### HIGH

**3. `sync-kit.sh` prints an EMPTY changelog on a version-prefix collision.**
`sync-kit.sh:94-99` stops at the first heading where `index($0, "## v0.1") == 1` — which
also matches `## v0.10`. Reproduced: with v0.10 in the changelog, a project at v0.1
received ZERO lines — the exact "empty report reads as no changes" case the script's own
comment warns about. Latent until v0.10, which the MAJOR.MINOR scheme guarantees will
exist. Additionally, `grep -q "^## v$have\b"` uses `\b` (a GNU extension, not POSIX) and
does not escape the dot in the version.

**4. The KIT-OWNED mechanism contradicts its own documentation and is fragile.**
`docs/UPDATING.md` lists the handoff skill as kit-owned and the file's header promises
"re-sync", but `sync-kit.sh:62` greps only `$kit/core` and `$kit/setup` — a kit-owned file
inside an overlay can NEVER be synced. Separately, detection is `grep -rl 'KIT-OWNED'`
anywhere in the file: a core document that merely MENTIONS the phrase in prose would be
silently overwritten wholesale. The marker must be anchored to a header line.

**5. `bootstrap.sh`'s STOPPING path fires after the damage.**
The gate-files-skipped check (`bootstrap.sh:125-140`) exits 1 AFTER `.kit-version` is
stamped and `core.hooksPath` is wired. A refused install still records "vX installed";
a later `sync-kit.sh` reports "already current. Nothing to do." on a project whose gate
was never installed. The skiplist check must run before any state is recorded.

### MEDIUM

**6. The comment-marker trap is shipped in three files by the repository that banned it.**
RESEARCH_LOG finding #5: an inline placeholder is only ever a quoted VALUE, never a
statement. Yet: `# {{TOOLCHAIN_SETUP_STEP}}` in `core/.github/workflows/ci.yml`,
`# {{STACK_IGNORE_RULES}}` in `core/.gitignore`, and `# {{BOUNDARY_GUARDS}}` inside the
commented-out list in `guard_boundaries.py`. A half-fill that keeps the leading `#` leaves,
respectively: a CI toolchain step that never runs (fail-closed, at least visible), ignore
rules that are inert, and an empty guard list (fail-open, invisible). `setup/INTERVIEW.md`
never warns that the `#` must go.

**7. The worked example in `boundary_checks.sh` teaches the fail-open calling pattern.**
The example is `hits=$(scan_grep '…' | grep '^src/domain/')` — it swallows return code 2,
the precise pattern `check.sh:191`'s own comment calls "reintroducing the bug". Whatever
fixes finding 1 must make this calling pattern safe or change the example.

**8. The unconfigured-build guard only catches a single space.**
`check.sh:299`: the case matches `""` and `" "` literally. `GATE_BUILD_CMD_OVERRIDE="  "`
(two spaces, or a tab) reaches `sh -c`, an all-blank command exits 0, and the gate goes
green with no build. Reproduced. Trim whitespace before testing.

### LOW

**9.** `unity_gate.sh --self-test` creates `unity/Logs/` and leaves stub result XMLs in the
real project tree; it should run against a temp project directory.
**10.** `bootstrap.sh copy_tree` iterates `find -print | while read` — breaks on a filename
containing a newline. Harmless today (kit-controlled input), inconsistent with the
NUL-safety stance everywhere else; a cheap guard that dies on such a name is enough.
**11.** `review.sh` exits 0 when the CLI exits 0 but the report has no `VERDICT:` line —
a cut-short review reads as success to a scripted caller. Warn-and-exit-0 should become a
distinct nonzero exit.

### Documentation debt attached to the fixes

  path has no negative test" entry both become false once finding 1 is fixed properly.
- `check.sh --self-test` closing message: same sentence.
- Finding 2 requires a backflow commit in the founding project.

VERDICT: Reject
